# КОНТЕКСТ И РОЛЬ
Наша задача — разработать рабочий веб-прототип (MVP) единой корпоративной HR-платформы «JanaМен». 
Цель прототипа — объединить разрозненные HR-сервисы в единое окно и показать идеальный сквозной пользовательский путь (E2E), строгую ролевую модель (RBAC) и готовность архитектуры к корпоративным интеграциям.

Наша задача сделать MVP проект - Digital HR платформу под названием JanaMen, задание поступило от сервиса JanaPost.

Стек :
Frontend – Angular и библиотеки, сборка через Bun
Backend – Go + sqlc
Database – supabase
Deploy – Cloudflare(frontend на собственном домене kilcdevs.net) and Google Cloud Run(backend)

[ Пользователь ] │ 
    ├─► [ Cloudflare Pages ] ────► Angular (Фронтенд SPA) │ 
    └─► [ Google Cloud Run ] ──► Go API (Бизнес-логика) 
  						                │ 
                                        ▼ 
                        (SSL / порт 6543) [ Supabase ] (PostgreSQL + Auth)

# 1. РОЛЕВАЯ МОДЕЛЬ (RBAC — проверка на уровне API и UI)
Доступ должен жестко проверяться на бэкенде (не только скрытием кнопок на фронтенде):
1. **Работник (Employee):** видит только свой профиль, свои заявки,перечень работы и поручений от руководителя, назначенные курсы и уведомления
2. **Руководитель (Manager):** видит всё то же, что работник + список сотрудников своего подразделения и их заявки на согласование. Доступ к данным чужих отделов строго запрещен (403 Forbidden).
3. **HR / Администратор (HR Admin):** видит все заявки, управляет базой знаний AI, назначает курсы и видит общую картину, имеет метрики и аналитику по всем сотрудникам и задачами

Так же у каждого работника и руководителя есть свой отдел их тоже будет три

1. Отдел поствок закаов - задачи по поставкам
2. Отдел логистики и склада - задачи по логистике и склада
3. Отдел IT и поддержки - задачи по технической поддержке и поддержка для клиентов

# 2. ФУНКЦИОНАЛЬНЫЕ КОНТУРЫ (MVP SCOPE)

## Контур 1: Единый вход и Дашборд
- Авторизация с быстрым переключением/входом под 3 тестовыми ролями.
- Главный экран (единое окно): сводка профиля, быстрые действия, активные заявки, задачи для отделов, прогресс обучения, виджет AI Jana и колокольчик уведомлений.

## Контур 2: Личный кабинет (Read-Only кадровые данные)
- Поля профиля: ФИО, компания, должность, подразделение, руководитель, дата приема, остаток дней отпуска.
- Официальные кадровые данные приходят из Mock-сервиса «1С:ЗУП» и доступны только для чтения (пользователь не может редактировать свою должность или остаток отпуска напрямую). Все отделы и регестрации сотрудников происходит только через HR-админа

## Контур 3: HR-сервис и «Мои заявки»
- Реализовать 1 полный сквозной сценарий: **«Заявка на отпуск»** (с проверкой остатка дней, количсетво отпусков которые потом будет видеть менеджер и принимать или отклонять) ИЛИ **«Заявка на аванс»**.
- Единый реестр «Мои заявки»: тип, дата создания, текущий статус.
- Карточка заявки: детали + история (таймлайн) изменения статусов (Создана → На согласовании у руководителя → Отправлена в Documentolog / Одобрена → Проведена в 1С:ЗУП).

## Контур 4: Jana Academy (Мини-LMS)
- Каталог курсов и блок «Назначенное обучение» (связан с профилем).
- Страница курса: просмотр учебного материала + короткий квиз/тест для проверки знаний.
- Фиксация прогресса (0% → 100%) и результата теста с сохранением в БД и отправкой уведомления.

## Контур 5: AI Jana (Безопасный RAG HR-ассистент)
- Чат-бот, отвечающий на типовые HR-вопросы строго по внутренней базе знаний (регламенты отпусков, авансов, больничных, обучения).
- **Обязательное требование 1 (Цитирование):** каждый ответ содержит точное название документа/раздела-источника и ссылку на него.
- **Обязательное требование 2 (Защита от галлюцинаций):** на вопросы вне базы знаний (или запросы чужих персональных данных) AI Jana НЕ выдумывает ответ, а сообщает об отсутствии точной информации и предлагает кнопку «Создать обращение в HR».

## Контур 6: Центр уведомлений
- Внутренние уведомления (список + индикатор непрочитанных).
- Обязательные триггеры:
  1. Изменение статуса заявки (создана / согласована / отклонена).
  2. Назначение нового курса или успешное завершение обучения в Jana Academy.

# 3. АРХИТЕКТУРА, ИНТЕГРАЦИИ И ЛОКАЛИЗАЦИЯ
- **Mock API внешних систем:** реальная интеграция не нужна, но необходимо выделить в коде отдельные адаптеры/модули (например, `1c-zup.adapter` и `documentolog.adapter`) с имитацией обмена данными:
- **Локализация (RU / KZ):** переключение языка интерфейса (Русский / Қазақша) через словарь локализации (i18n).
- **Инфраструктура:** запуск через `docker-compose up` с автоматическим заполнением БД тестовыми данными (Seed Data).

# 4. ШЕСТЬ КЛЮЧЕВЫХ СЦЕНАРИЕВ ДЕМОНСТРАЦИИ (ЧЕК-ЛИСТ ЗАЩИТЫ)
Весь код и UI должны безупречно проводить жюри по этим 6 шагам:
1. **Вход и обзор:** Работник входит в JanaМен и на одном экране видит профиль, быстрые сервисы, заявки, обучение и уведомления.
2. **Оформление заявки:** Работник подает заявку на отпуск/аванс → заявка появляется в списке со статусом и историей.
3. **Роль Руководителя и безопасность:** Руководитель входит в систему, видит и одобряет заявку своего подчиненного (у работника меняется статус и приходит уведомление). При попытке запроса данных чужого отдела API возвращает отказ в доступе.
4. **Обучение:** Работник открывает назначенный курс в Jana Academy, читает материал, сдает мини-тест → прогресс становится 100%, приходит уведомление.
5. **Штатный ответ AI Jana:** Работник спрашивает правило (например, «Как рассчитывается отпуск?») → получает точный ответ со ссылкой на регламент.
6. **Нештатный вопрос AI Jana (Guardrails):** Работник задает вопрос вне базы (или спрашивает зарплату коллеги) → AI Jana отказывается галлюцинировать и предлагает эскалацию в HR.

# 5. ЧТО ДЕЛАТЬ НЕ НУЖНО (OUT OF SCOPE — ЭКОНОМИМ ВРЕМЯ)
- НЕ делать нативное мобильное приложение (достаточно аккуратной адаптивной веб-версии).
- НЕ делать реальную ЭЦП и файловое хранилище оригиналов документов.
- НЕ делать модули рекрутинга, Performance Management и прочие будущие HR-блоки.
- НЕ поручать AI принятие кадровых решений (AI только консультирует).
- НЕ использовать реальные ПДн и не коммитить API-ключи/пароли в репозиторий (использовать `.env.example`).

# 6. КРИТЕРИИ ОЦЕНИВАНИЯ (ФОКУС КОМАНДЫ)
- **30% — Сквозной сценарий:** бесшовная связка «вход → профиль → заявка → согласование → уведомление» + работающие обучение и AI.
- **20% — Функциональность и UX:** чистый единый интерфейс, минимум кликов, адаптивность.
- **20% — Архитектура и код:** честный RBAC на бэкенде, чистая схема БД, понятные точки подключения 1С:ЗУП и Documentolog(не обязательно, но судбям нужно написать в README как нужно сделать интеграцию)
- **15% — AI Jana:** точность ответов по базе, видимые источники, жесткий фильтр от выдумок.
- **10% — Jana Academy:** рабочий флоу прохождения курса и связь с профилем.
- **5% — Защита:** четкое разделение на «Реализовано / Замокано / Roadmap», схема архитектуры и живое демо.
