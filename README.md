# «JanaMen» — Digital HR-платформа для JanaPost 🚀

> **MVP корпоративной HR-платформы «JanaMen»**, разработанный в рамках хакатона для сервиса **JanaPost**.  
> Объединяет разрозненные HR-сервисы в единое окно, обеспечивает строгий ролевой доступ (RBAC), безопасный RAG-ассистент AI Jana с цитированием регламентов и защитой от галлюцинаций, а также мини-LMS Jana Academy.

---

## 🏗 Архитектура системы

```
[ Пользователь / Браузер ]
      │
      ├─► [ Cloudflare Pages ] ────► Angular 22 (SPA на домене kilcdevs.net)
      │
      └─► [ Google Cloud Run ] ────► Go API (Chi + sqlc, чистая бизнес-логика)
                                        │
                                        ├─► [ Supabase ] (PostgreSQL 16 + Auth)
                                        ├─► [ 1C:ZUP Adapter ] (Mock API кадрового учёта)
                                        └─► [ Documentolog Adapter ] (Mock API СЭД)
```

- **Frontend:** Angular 22 (Signals, Standalone Components, SCSS, корпоративная палитра JanaPost `#00A859`, сборка через **Bun**).
- **Backend:** Go 1.27 + **sqlc** (типобезопасные SQL-запросы без тяжелых ORM-прослоек), Chi Router.
- **Database:** PostgreSQL (Supabase).
- **Deploy:** 
  - Фронтенд: **Cloudflare Pages** (кастомный домен `kilcdevs.net`).
  - Бэкенд: **Google Cloud Run** (Docker container на базе Alpine).
- **Локализация:** Полная поддержка двух языков интерфейса — **Русский (RU)** и **Қазақша (KZ)** с переключением в 1 клик.

## 👥 Ролевая модель (RBAC) и тестовые учетные записи

В системе реализован быстрый **переключатель демо-ролей в шапке сайта (в 1 клик)**, а также разделение по 3 ключевым отделам JanaPost:
1. **Отдел поставок заказов**
2. **Отдел логистики и склада**
3. **Отдел IT и поддержки**

| Роль | Тестовый аккаунт | Должность / Отдел | Доступные функции |
|---|---|---|---|
| **Работник (Employee)** | `employee.supply@janamen.kz` (Алия Бекова) | Специалист по поставкам (Отдел поставок) | Профиль (1С read-only), баланс отпусков (24 дн.), подача заявок, задачи от руководителя, прохождение курсов в Jana Academy, AI Jana. |
| **Руководитель (Manager)** | `manager.supply@janamen.kz` (Ерлан Нұрланов) | Руководитель отдела поставок | Всё, что у работника + входящие заявки на согласование своего подразделения. **Доступ к чужим отделам строго заблокирован (403 Forbidden)**. |
| **HR / Администратор (HR Admin)** | `hr@janamen.kz` (Айгерим Сатпаева) | HR-директор компании | Сквозной доступ по всем отделам, сводная HR-аналитика, назначение курсов, управление базой знаний AI Jana и эскалациями. |

## 📋 6 Ключевых сценариев демонстрации (Чек-лист защиты)

Система полностью готова к показу жюри по 6 обязательным шагам:

### 1. Вход и обзор единого окна (Dashboard)
- Работник входит в платформу и на одном экране видит сводку профиля из 1С:ЗУП, остаток дней отпуска (24 дня), активные заявки, рабочие поручения руководителя отдела, прогресс в обучении и виджет AI Jana.

### 2. Оформление заявки и сквозной таймлайн
- Работник нажимает «Заявка на отпуск» или «Заявка на аванс».
- Платформа проверяет остаток дней (при превышении 24 дней выдается валидация).
- Заявка создается и отображает интерактивный таймлайн согласования:  
  `Создана сотрудником` ➔ `На согласовании у руководителя` ➔ `Отправлена в Documentolog` ➔ `Проведена в 1С:ЗУП`.

### 3. Роль Руководителя и безопасность (RBAC & 403 Forbidden)
- В шапке переключаемся на **Руководителя**.
- Руководитель видит заявку Алии Бековой и нажимает «Согласовать». Заявка переходит в СЭД Documentolog, проводится в 1С:ЗУП со списанием дней отпуска, а сотруднику поступает уведомление.
- Нажимаем кнопку **«🛡️ Проверить блокировку чужого отдела»** — бэкенд на уровне API отклоняет запрос с ошибкой **`403 Forbidden`**, подтверждая изоляцию данных отделов.

### 4. Обучение в Jana Academy (Мини-LMS)
- Работник открывает курс «Информационная безопасность» или «Стандарты сервиса JanaPost».
- Читает регламент на русском или казахском языке и переходит к интерактивному квизу.
- После сдачи теста результат фиксируется в БД, прогресс становится **100%**, и в колокольчик приходит уведомление о завершении обучения.

### 5. Штатный ответ AI Jana (RAG с точным цитированием)
- Нажимаем проверочную кнопку: *«Как рассчитывается отпуск?»*.
- AI Jana находит статью в базе регламентов и выдает структурированный ответ с **точным названием документа, разделом и ссылкой**:  
  `📄 Источник: «Регламент ежегодных отпусков», Раздел 2. Расчёт отпуска`.

### 6. Защита от галлюцинаций и утечки ПДн (Guardrails)
- Нажимаем *«Сколько составляет зарплата начальника?»* ➔ AI Jana немедленно блокирует запрос и разъясняет правила конфиденциальности персональных данных.
- Нажимаем вопрос вне базы знаний (например, *«Какая погода на Марсе?»*) ➔ AI Jana отказывается придумывать факты от себя и отображает кнопку **«📩 Создать обращение в HR»**.

## 🔌 Интеграции внешних систем (Mock vs Production)

В соответствии с корпоративными стандартами архитектуры JanaPost в коде выделены независимые адаптеры:
- `backend/internal/integrations/zup1c/zup1c.go` (`1c-zup.adapter`)
- `backend/internal/integrations/documentolog/documentolog.go` (`documentolog.adapter`)

### Как подключить реальные сервисы (Roadmap):
1. **1С:ЗУП (КОРП 3.1):**
   - На стороне 1С публикуется HTTP-сервис или OData-интерфейс (`/odata/standard.odata/Catalog_Сотрудники` и `/Document_ОтпускаОрганизаций`).
   - В адаптере `zup1c.go` структура `Mock` заменяется на `ProductionClient`, выполняющий базовую HTTP-аутентификацию с сервером 1С.
2. **СЭД Documentolog:**
   - Подключение по REST API Documentolog: метод `POST /api/v1/documents` создает входящий проект приказа, передает маршрут согласования и возвращает `doc_id`.
   - Webhook от Documentolog переводит статус заявки в `completed` после подписания ЭЦП.

## 🚀 Инструкция по запуску

### Вариант 1: Запуск через Docker Compose (Рекомендуемый)
```bash
docker-compose up --build
```
- Бэкенд запустится на `http://localhost:8080` с автоматической миграцией схемы и заполнением демо-данными (Auto-Seed).

---

### Вариант 2: Локальный запуск без Docker

#### 1. Бэкенд (Go + sqlc):
```bash
cd backend
go run ./cmd/api
```
*(При необходимости перегенерации SQL-запросов: `sqlc generate`)*

#### 2. Фронтенд (Angular + Bun):
```bash
cd frontend
bun install
bun start
```
Приложение откроется на `http://localhost:4200`.

## 🌐 Деплой в Cloudflare Pages и Google Cloud Run

### Фронтенд (Cloudflare Pages под `kilcdevs.net`):
1. Сборка продакшн-бандла:
   ```bash
   cd frontend
   bun run build
   ```
2. Деплой через Wrangler:
   ```bash
   bun x wrangler pages deploy dist/frontend/browser --project-name=janamen
   ```
3. Статический роутинг SPA настроен в `public/_redirects`.

### Бэкенд (Google Cloud Run):
Сборка и публикация контейнера из `backend/Dockerfile`:
```bash
gcloud builds submit --tag gcr.io/[PROJECT_ID]/janamen-backend backend/
gcloud run deploy janamen-backend --image gcr.io/[PROJECT_ID]/janamen-backend --platform managed --allow-unauthenticated
```
